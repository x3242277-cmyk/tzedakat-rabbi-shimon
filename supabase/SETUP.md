# מעבר ל-Supabase — הושלם ✅

המערכת עברה במלואה מגוגל שיטס ל-Supabase. סיכום מה שנעשה:

## מה קיים היום
- **טבלאות**: `members`, `donations`, `expenses`, `purim_addresses`, `grants_archive`, `settings`, `profiles` (ראה `schema.sql`).
- **אבטחה (RLS)**: רק משתמש מחובר (authenticated) יכול לקרוא/לכתוב. משתמש לא מחובר (anon) חסום לגמרי — נבדק ואומת.
- **נתונים**: כל הנתונים הקיימים הועברו — 442 בחורים, 1,260 הפקדות, 348 הוצאות, 566 כתובות פורים, היסטוריית מענקים (תשפ"ד-תשפ"ו), הגדרות מערכת.
- **משתמשים**: 4 המשתמשים הקיימים (מנהל, מנדי בידרמן, מוישי גולדברג, אלימלך גלבשטיין) הועברו עם **אותן הסיסמאות** שהיו להם, כך שההתחברות ממשיכה לעבוד בדיוק כמו קודם — רק שעכשיו זו התחברות מאובטחת אמיתית (Supabase Auth) במקום השוואת טקסט גלוי.
- **קוד**: `supabase-integration.js` (חדש) הוא שכבת החיבור; `script.js` עודכן להשתמש בה במקום בגוגל שיטס.

## התחברות
במסך הכניסה מקלידים **שם משתמש** וסיסמה. שם המשתמש הוא החלק שלפני ה-@ בכתובת הטכנית של החשבון ב-Supabase Auth, והקוד משלים את הדומיין `@tzedaka.local`. לדוגמה: מי שהחשבון שלו הוא `admin@tzedaka.local` מקליד `admin`.

בקוד אין רשימת משתמשים. שם התצוגה בעברית נלקח אחרי ההתחברות מטבלת `profiles` (העמודה `display_name`, ואם היא ריקה או לא בעברית – העמודה `username`).

הודעת השגיאה במסך הכניסה אחידה ("שם משתמש או סיסמה שגויים") ולא מגלה אם המשתמש קיים.

## סשן ונתונים בדפדפן
- הסשן ועותק הנתונים נשמרים ב-`sessionStorage`: רענון דף משאיר את המשתמש מחובר, סגירת הדפדפן מנתקת ומוחקת. כל לשונית מתחברת בנפרד.
- תור השמירות הממתינות (`ezer_pending_writes`) נשאר ב-`localStorage`, כדי ששינויים שלא נשלחו לשרת לא יאבדו.

## עדכון אבטחה — להריץ פעם אחת ⚠️
הקובץ `security-update.sql` מוסיף:
- **הרשאות שנאכפות בשרת** (לא רק במסך): הוצאות רק למי שיש לו הרשאת "הוצאות", פורים רק עם הרשאת "הכנסות", מענקים וקבלות רק עם הרשאת "מענקים", עריכה רק עם הרשאת "עריכה", ומחיקות והגדרות מערכת רק למנהל.
- **חסימה של שינוי הרשאות עצמי** — עד העדכון, כל משתמש יכול היה לתת לעצמו הרשאות מנהל.
- **יומן פעולות** (טבלת `audit_log`): מי רשם / שינה / מחק ומתי. מוצג בהגדרות → "יומן פעולות".
- **תיקייה מאובטחת לקבלות** (Storage bucket בשם `receipts`) לתשלומים לחנויות.

איך מריצים: Dashboard → **SQL Editor** → New query → מדביקים את כל התוכן של `security-update.sql` → **Run**. אפשר להריץ שוב בלי נזק.

## ניהול משתמשים
1. **הרשאות** (מה כל משתמש רואה ועושה): באפליקציה, הגדרות מערכת → "משתמשים" — מסמנים ולוחצים "שמור" (עובד אחרי הרצת עדכון האבטחה).
2. **הוספה / מחיקה / איפוס סיסמה**: Dashboard → **Authentication → Users**.
3. משתמש חדש: יוצרים אותו עם מייל בסגנון `name@tzedaka.local`, ומעדכנים את `display_name` שלו בטבלת `profiles` לשם בעברית. אין צורך לשנות קוד.

## מפתחות
- **anon key** (הציבורי, מוטמע בקוד) — בטוח, מוגן ע"י RLS.
- **service_role / סיסמת מסד** — שימשו רק חד-פעמית להעברת הנתונים, לא נשמרו בקוד ולא בצ'אט. מומלץ (לא חובה) לאפס אותם ב-Settings → Database / API מעכשיו, כשההעברה הושלמה.

## גיבוי מהמערכת הישנה
קובץ ה-Apps Script של גוגל שיטס עדיין קיים בגוגל (לא נמחק), רק שהאפליקציה כבר לא פונה אליו. אפשר להשאיר אותו כגיבוי היסטורי.
